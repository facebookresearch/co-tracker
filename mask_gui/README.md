# Instance Mask Picker

A small browser GUI (Flask + OpenCV, served from Docker) for turning a
color-coded instance-segmentation video — like `demo_008_instance.mp4` — into
a binary mask, by clicking the color blocks you want.

## Run it

Everything needed to run the tool lives in this `mask_gui/` folder. From
inside it:

```bash
cd mask_gui
docker compose up --build
```

Then open http://localhost:5000 in a browser.

The parent project directory (one level up from `mask_gui/`, i.e. where your
video files live) is mounted into the container at `/data`, so any `*.mp4`
anywhere under the project (not just top-level, and including inside
`mask_gui/` itself if you ever put one there) shows up in the video
dropdown, and everything the tool saves lands in `../output/` on the host
(next to `mask_gui/`, not inside it). The service uses Docker's host
networking (`network_mode: host`) rather than the default bridge network,
because this environment's bridge network has no working DNS/NAT; on a
normal Docker setup you can switch back to bridge + a `ports:` mapping if
you prefer the extra isolation.

## Using it

Each instance in these videos is a flat, solid color held for the entire
clip, so there's no need to track anything frame-to-frame — a mask is just
"pixels close enough to one of the colors you picked", recomputed
independently on every frame.

1. Pick the video from the dropdown and click **Load**.
2. **Click on a color block** anywhere in the frame. The exact pixel color is
   sampled from the decoded frame and added as a chip. Click as many
   different blocks as you like (on the same frame or after scrubbing to a
   different one) — they all get combined into **one** mask.
   - **Tolerance** controls how close a pixel's color must be to a selected
     color to count (raise it if compression noise is splitting a block;
     lower it if it's bleeding into a neighboring instance).
   - **clean up noise** applies a small morphological open/close to remove
     stray pixels from video-compression artifacts.
   - **invert selection** flips the mask to everything *except* the colors
     you picked (e.g. pick one object and invert to mask "everything else",
     or pick the background color and invert to mask "every instance").
   - Click the `x` on a chip to remove that color, or **Clear selection** to
     start over.
3. Click **Generate & save mask**. This computes the combined mask for every
   frame of the video and saves it. The result appears under **Saved
   masks**, with the fraction of frames it was non-empty in.
4. Click **View** on a saved mask to load it into the right-hand preview
   pane, then scrub the frame slider and toggle **overlay / mask / raw** to
   check it against the original video, frame by frame.
5. Click **Download .npy** on any saved mask to grab `mask_stack.npy` — a
   single boolean array of shape `(num_frames, H, W)`, one frame per index,
   directly loadable with `numpy.load(...)`.

### Loading an existing mask .npy

Use **Load an existing mask .npy** to visualize a mask that wasn't
generated by this GUI -- for example output from `batch_generate_masks.py`,
or something downloaded earlier. Pick the file from the dropdown (it scans
the whole mounted project for `*.npy` files) and click **Load mask**; it
gets registered as a regular saved mask for the currently loaded video, so
you can preview it (overlay/mask/raw, frame by frame) and download it the
same way as any other. It must be a boolean/0-1 array shaped
`(num_frames, H, W)` matching the loaded video (a single-frame `(1, H, W)`
array is also accepted and held for every frame). Click **Refresh list** if
a file was added after the page loaded.

Everything the tool saves (for every generated mask, whether or not you
download it) lives on the host under
`../output/<video_path_with_slashes_as___>/<mask_id>/` (next to `mask_gui/`,
not inside it), as `mask_stack.npy` + `meta.json` (the selected colors,
tolerance, and how many frames the mask was non-empty in). You can generate
as many separate masks as you like from the same video (e.g. one per
object, or one combining several objects) — each generated mask gets its
own id.

### Batch-generating masks for a whole folder of demos

`batch_generate_masks.py` (also in this folder) does the same per-frame
color-threshold the GUI does, but walks every `demo_***/` folder in one shot
and writes `demo_***_instance_mask.npy` straight into each folder, rather
than going through the browser one video at a time.

If you have opencv-python and numpy installed already:

```bash
python3 mask_gui/batch_generate_masks.py                       # defaults to ../not_reviewed
python3 mask_gui/batch_generate_masks.py --dir /path/to/folder # process a different folder instead
```

**On a machine without those installed** (e.g. copy just the `mask_gui/`
folder elsewhere), build the small standalone image instead -- no Flask, no
GUI, just the script and its two dependencies:

```bash
cd mask_gui
docker build -f Dockerfile.batch -t mask-batch .

# run against a folder of demo_*** subfolders -- --user keeps the output
# files owned by you instead of root:
docker run --rm --user "$(id -u):$(id -g)" -v /path/to/not_reviewed:/data mask-batch

# or point it at a subfolder of whatever you mounted:
docker run --rm --user "$(id -u):$(id -g)" -v /path/to/parent:/data mask-batch --dir /data/some_subfolder
```

(If the build can't resolve DNS, retry with `docker build --network host ...`
-- see the comment at the top of `Dockerfile.batch`.)

See the comment at the top of `batch_generate_masks.py` for more on what
color it uses and other options.

## Notes

- Picking relies on each instance having a distinct, stable color; if two
  different instances happen to share a near-identical color, raise/lower
  tolerance or add more distinguishing colors to tell them apart.
- State (loaded video frames, in-progress selections) lives in the
  container's memory; restarting the container just means reloading the
  video from the dropdown. Saved masks on disk persist across restarts and
  are reloaded automatically when you hit "View".
